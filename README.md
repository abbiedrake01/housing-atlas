# Housing Atlas

An interactive UK basemap showing England's non-profit housing associations, their owned social homes, reported local-authority footprints and tenant satisfaction.

## Features

- House clusters proportional to owned stock, with hover territory shading.
- Individual association selection, region, stock size and weekly rental rent filters.
- Separate LCRA (rental) and LCHO (ownership) views; all-homes mode keeps LCRA satisfaction scores.
- TP01–TP12 scores, year-on-year percentage-point changes, and a filter for the displayed value.
- Operational RP, CH, BS and NM measures, with original units, YoY changes and value filters.
- Pearson/Spearman correlation explorer with pair selection, scatterplots, ranked relationships and a clickable matrix across the filtered cohort.
- An Abri-inspired palette with self-hosted Nunito Sans. This is an independent project, not an Abri service.

## Run locally

Use Node.js 22.13 or newer and pnpm 11.19.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

```sh
pnpm test
pnpm build
pnpm preview
```

`dist/` contains the complete static site. No server, API token, database or ChatGPT account is required. The app and bundled data work under a repository subdirectory such as `/housing-atlas/`.

## Publish on GitHub Pages

1. Create a **new public repository named `housing-atlas`**, without a README, licence or `.gitignore` generated by GitHub. Do not reuse another repository.
2. Push this local repository's `main` branch to that new remote.
3. In **that repository only**, open **Settings → Pages → Build and deployment → Source**, and choose **GitHub Actions**.
4. Open **Actions → Deploy Housing Atlas to GitHub Pages → Run workflow** if the first push happened before Pages was enabled.

The included workflow tests and builds on pushes to `main`, then deploys `dist/`. Its deployment step displays the actual Pages URL, normally `https://YOUR-USERNAME.github.io/housing-atlas/`.

No personal access token or repository secret is needed for the workflow; it uses the repository-scoped `GITHUB_TOKEN`. Account/organisation policy may require an administrator to enable Actions or Pages. Repository creation and Pages settings require appropriate GitHub permissions.

Official instructions: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

## Data and interpretation

The bundled snapshot was downloaded on 7 September 2026. It is not a live feed.

- [RSH 2024/25 tenant satisfaction data](https://www.gov.uk/government/statistics/tenant-satisfaction-measures-202425)
- [RSH 2023/24 tenant satisfaction data](https://www.gov.uk/government/statistics/data-release-tsm-2024)
- [RSH 2025 stock, group structure and rents](https://www.gov.uk/government/statistics/private-registered-provider-social-housing-stock-and-rents-in-england-2024-to-2025)
- [ONS December 2024 local authority boundaries](https://www.arcgis.com/home/item.html?id=6a05f93297cf4a438d08e972099f54b9)

Only non-profit private registered providers are included; councils and for-profit providers are excluded. Scotland, Wales and Northern Ireland are basemap context, not covered by this England dataset. The snapshot includes 1,076 providers with reported stock. Many smaller providers lack centrally published satisfaction scores.

LCRA and LCHO stocks reconcile to the all-homes totals. Managed-only stock is excluded. One displayed house represents up to 2,000 owned units/bedspaces, rounded up. Local-authority shading represents reported stock presence, not precise property locations or a continuous service boundary. Clusters are displaced slightly for legibility from stock-weighted geographic centroids.

TP02–TP04 are not applicable to LCHO. Missing/suppressed data remains missing. YoY matches registration codes without adjustment for mergers, tenant mix or survey methods. Correlations are unweighted, provider-level, pairwise complete Pearson or Spearman coefficients with at least three observations; they are not causal effects. Rent is a stock-weighted general-needs net social rental rent, excluding service charges, Affordable Rent, intermediate rent and HIST. It does not apply to the LCHO view.

See **About the data** in the app for further details.

## Ridge regression tab

Separate fixed-cohort models of 2024/25 TP01 for LCRA and LCHO use log10 tenure-specific owned homes, either applicable other TP scores or operational TSMs, and reference-coded region (London baseline). The atlas filters do not affect these national models. LCHO excludes inapplicable TP02–TP04. Satisfaction models use 189 LCRA and 53 LCHO complete cases. Operational models use 185 LCRA and 53 LCHO complete cases. The operational specification omits TP02–TP12; it estimates operational associations conditional on the other operational measures, size and region. Families can have different complete-case cohorts, so the difference in predictive performance is not a controlled feature-set comparison.

All predictor columns are standardized inside each training fold. Ridge includes an unpenalized intercept. Alpha is tuned over 29 logarithmic values from 0.001 to 10,000 by inner five-fold CV. Outer five-fold predictions provide held-out R², RMSE and MAE. A separately tuned full-cohort fit supplies coefficients and partial-residual plots. Numeric coefficients are TP01 percentage points per cohort SD; region coefficients are differences from London. Group-removal comparisons retune their reduced models inside the same outer folds.

The UI includes coefficient rankings, actual/predicted scatter, a selectable partial-residual plot, regional contrasts, residual histograms and a tuning curve. These are conditional provider-level associations, not causal effects or significance tests.

To rebuild the models after changing the source data:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/regression-requirements.txt
.venv/bin/python scripts/fit-regression.py
.venv/bin/python scripts/check-regression.py
pnpm test
pnpm build
```

Commit the regenerated `public/regression.json` alongside data changes. Tests reject a stale source-data checksum and validate fold partitions, coefficient algebra and reported metrics. Model fitting runs locally, not in visitors' browsers. No Python runtime is required to host the site.

## Operational data

`data/operational-metrics.json` defines all 14 operational components in the 2024/25 snapshot:

- RP01: homes failing Decent Homes Standard (%); RP02_1/_2: non-emergency/emergency repairs within provider targets (%), **LCRA only**.
- CH01_1/_2: stage 1/2 complaints per 1,000 homes; CH02_1/_2: stage 1/2 responses within Complaint Handling Code timescales (%), **tenure-specific**.
- BS01–BS05: required gas, fire, asbestos, legionella and lift checks (%); NM01_1/_2: ASB cases/hate incidents per 1,000 homes, **combined LCRA + LCHO**.

All-homes mode retains LCRA RP/CH values and combined BS/NM values. Combined complaints are never substituted for missing tenure-specific complaints. Missing/suppressed/inapplicable values remain null, not zero. Operational map colours encode magnitude rather than a performance rating; higher complaint or ASB reporting is not automatically worse performance. Rates may exceed 100. YoY rates are differences per 1,000 homes, whereas percentage changes are in percentage points. CH02 comparisons may be affected by Complaint Handling Code changes; RP02 uses each landlord's own target. Newer measures outside the 2024/25 specification are not backfilled.

Values are joined to existing atlas reporting groups by exact registration code, without aggregating member rates. 193 atlas providers match a published management-information record. Source URLs and input SHA-256 hashes are embedded under `operationalSource` in `public/housing.json`.

To reproduce ingestion, download the [2025 full-data ZIP](https://assets.publishing.service.gov.uk/media/6939474f7a605b2d61cd901a/TSM_2025_Full_Data.zip), extract `TSM_2025_Full_Data - File 04 - Management_info.csv`, and download the [2024 v2.1 workbook](https://assets.publishing.service.gov.uk/media/69394574e447374889cd9004/2024_TSM_Full_Data_v2.1_FINAL.xlsx). With `openpyxl==3.1.5` installed:

```sh
python scripts/import-operational.py --current /path/to/management.csv --previous /path/to/2024.xlsx
python scripts/fit-regression.py
python scripts/check-regression.py
pnpm test
```

The correlation explorer always uses current-year levels and all current explorer filters (including a selected value/YoY range). It ranks absolute correlations, handles Spearman ties with average ranks, and reports each pair's sample size. Its plotted line is unadjusted OLS in raw units even when Spearman is selected. Sparse/constant pairs have no coefficient. Multiple comparisons and complete-case selection are exploratory, with no causal or inferential claims.

## Annual data selector

The header's **Data year** selector defaults to 2025/26 and retains the original 2024/25 snapshot. Switching year resets filters and selections and switches stock, rent, TP/operational results, correlations and all four separately fitted ridge models together. `data/years.json` maps each selection to its files. The older `housing.json` and `regression.json` remain unchanged.

2025/26 uses the RSH TSM v1.1 release (5 November 2026) and PRP stock/rents v1.1 for 31 March 2026, downloaded 20 November 2026. It includes 1,063 non-profit reporting groups/standalone providers with owned stock; councils and for-profit providers remain excluded. The import reconstructs reporting groups from the current registered-parent hierarchy, rather than carrying forward last year's provider population or stock. Missing/suppressed observations remain null. YoY matches registration codes against the retained 2024/25 snapshot, without merger adjustments or rebasing to later revisions.

The 2025/26 source reports more detailed predominant regions; the model uses these categories with London as reference, excluding unreported/inapplicable region values. Region granularity and provider cohorts therefore differ between years. The contextual basemap retains ONS December 2024 geometry. Barnsley and Sheffield's new 2025 codes are matched by exact authority name to approximate historical footprints, explicitly disclosed in the app.

Reproduce the new snapshot and fits:

```sh
python scripts/import-2026.py --download
python scripts/fit-regression.py --year 2025-26
python scripts/check-regression.py
pnpm test
pnpm build
pnpm check:pages
```

The importer records official source URLs, input archive hashes and the prior snapshot hash in `public/housing-2025-26.json`. Model checks cover both years and both predictor families. Default `fit-regression.py` behavior still rebuilds only 2024/25; specify `--year 2025-26` for the new year.

### 2023/24 and 2027 projections

The 2023/24 selector uses the revised RSH TSM workbook and March 2024 stock and rents release. Rebuild it with `python scripts/import-2026.py --year 2024` (requires openpyxl), then run `python scripts/fit-regression.py --year 2023-24`. There is no earlier TSM year in the atlas.

The 2027 tab fits TP01 separately for LCRA and LCHO on the three reporting years ending March 2024, 2025 and 2026. It matches providers by exact registration code and requires a published score in each year. The cohort view averages the same providers in each year, with equal weight. For observations `a, b, c`, the annual OLS slope is `(c - a) / 2` and the March 2027 projection is `(a + b + c) / 3 + (c - a)`. Estimates are unadjusted for changes in provider structure, surveys, region and tenure mix. Raw extrapolations outside 0–100% are flagged.

The default 2027 forecast uses a pooled one-year-ahead ridge model. Select a tenure and one TP outcome. Predictors are all applicable prior-year TP scores, including the lag of the outcome. Training pools 2024→2025 and 2025→2026 by registration code within tenure, using complete predictor/outcome rows. The temporal backtest fits the first transition alone and tests on the second, against carrying forward the preceding score. The forecast refits on both transitions and scores all providers with complete 2025/26 inputs. The earlier straight-line TP01 baseline remains available for comparison.

Regenerate the downloadable forecast data with `python scripts/fit-forecast.py` in the regression environment.

The pooled forecasts also use prior-year RP and CH measures (CH only for LCHO). Each missing operational input is replaced by its observed mean from the corresponding training fit. The forward backtest calculates means using the first transition only. Predictors are standardized within each training split. Five-fold provider-grouped cross-validation on 2024→2025 chooses λ for the objective mean squared error + λ × squared norm of standardized slopes. The intercept is unpenalized, and λ stays fixed for the pooled refit. Coefficients are reported in original units with provider-clustered sandwich standard errors. Coefficient-to-SE ratios are descriptive for the penalized fit. Vite gives the forecast data a content-hashed asset URL so the code and data stay in sync across deployments.

The forecast target can be any applicable TP, RP, CH, BS or NM measure. BS/NM outcomes use the published combined-tenure scope within the selected analysis cohort, with the outcome's lag added to the baseline TP/RP/CH predictor set. Missing operational predictors use training means; missing outcomes are excluded. The backtest reports each measure in its native units, with carry-forward comparisons on common rows. The coefficient display ranks fully standardized effects, and hides `|β| < 0.05` by default without changing the default fit. The optional zeroing mode removes those slopes, recentres the intercept at the training mean, and updates projections and backtest RMSE.
